# 复现报告：Steering LLMs between Code Execution and Textual Reasoning (ICLR'25)

> 对象论文：*Steering LLMs between Code Execution and Textual Reasoning*（arXiv 2410.03524，ICLR'25）
> 复现子集：15 个任务 × 5 个方法 × 3 种思考模式，主模型 DeepSeek（`deepseek-flash`），2026-11-19 完成。

---

## 1. 一句话结论

**论文的核心结论方向被复现出来了**：在 15 个任务上，`Code+Text+Sum.`（代码 + 文本 + 汇总器）在三种思考模式下**平均分都是第一名**（AveNorm 99.4 / 99.4 / 99.7），而"让模型多写代码"本身并不能稳定提升成绩（`All Code+CoT` 在 A 组只有 77.2，远低于纯文本的 88.8）。

但有三处必须打折：①本轮最高分已接近上限（多数任务 96~100%），**方法间差异被天花板效应压缩**，而且在少数任务上 Sum 并不是第一（如 A 组的 Letters(sentence)：OnlyQ 88 > Sum 80）；②B 组有 2 个任务的 0% 是输出预算被思考耗尽造成的假象（已单独做敏感性重跑：预算提到 8000 后回到 12~40%，见第 6 节）；③BoxNet / Path Plan / BoxLift 三个规划任务在 2500 预算下普遍只有 0~25%，是预算与模型能力共同限制，不能用来区分方法优劣。

## 2. 实验设置

| 项目 | 设置 |
|---|---|
| 仓库 | `CodeSteer-v1.0`（原地不动，所有补丁在 `repro/` 里 monkey-patch） |
| 主模型 | DeepSeek `deepseek-flash`（思考模式下有 `reasoning_content`） |
| 裁判模型 | 同为 `deepseek-flash`，但**永远关闭思考**（否则三组之间的分数变化分不清是主模型还是裁判变了） |
| 任务 | 论文 Table 2 的 14 个任务 + 自加的第 15 个任务「英文字句字母计数」 |
| 方法 | 5 个：`1_only_ques`(OnlyQ)、`All_text`、`All_code_CoT`、`AutoGen`、`Text_code_summarizer`(Code+Text+Sum.) |
| 砍掉的方法 | `Code Interpreter` 系列（国产模型无 CI 通道）、`AutoGen System`（runner 未接 system message 分支）、`Self-estimate Score`（仓库未实现） |
| 样本量 | 每任务 25 个（A 组原始跑到 50，统计时统一按前 25 个算；navigate 因 A 组只出 11 个，三组统一按 11 个比） |
| 代码执行 | 子进程，超时 30s（论文 30s） |
| 思考模式 | A = `off`（不带思考）；B = `strip`（开思考但**丢弃** `reasoning_content`，只把 `content` 往下游传）；C = `on`（把 `reasoning_content + content` 一起往下游传） |
| 思考预算 | 2500 tokens（敏感性实验用 8000） |
| 归一化 | `AveNorm_j = (1/N) Σ_i s_ij / max_i(s_i)`（论文口径，但 max 只在我这 5 个方法里取，论文是 10 个方法，所以绝对值不可直接比，**名次和方向可比**） |

规模：合计 **24,865 次 API 调用**，输入 16.2M tokens、输出 10.5M tokens；按 DeepSeek 官方价目表（`deepseek-flash`：输入 1~2 元/百万，输出 4~8 元/百万，空闲时段半价）折算约 **58~116 元**人民币。其中正式三组 23,648 次调用（约 44~87 元），敏感性重跑 1,217 次调用（约 15~29 元）。

> 上面只是**产出结论的那部分**。把两次返工（修 `-c` 路径 bug 之前的一夜、思考预算误设 8000 的一夜）和冒烟测试都算上，整轮复现共调用 **56,084 次、输入 34.34M / 输出 20.61M tokens，约 117~234 元**（缓存命中口径下 83~166 元）。完整账单与省钱建议见**第 10 节**。

| Blocksworld | **15%** | 0% | 92% | 21% | 0% |

三点观察：

1. **"只给问题"（OnlyQ）时模型会自发写代码**：Blocksworld 15%、Path Plan 14%。这正对应论文说的"模型对代码通道的偏好/过度自信"——没人让它写，它自己写。

| 纯文本（All Text）未必比只给问题好 | A 组 88.8 < OnlyQ 90.3（B/C 组则相反） | ⚠️ 部分一致，依赖性于是否开思考 |

**关键差异（必须说明）**：

1. **分数天花板**。论文里 GPT-4o 的 AveNorm 是 80 上下，本次多数任务 96~100%，方法差异被压缩到几个点以内。原因是 2026 年的 `deepseek-flash` 已在 MATH/GSM/BBH 上很强，任务本身对它是"送分题"。真正能区分方法的只剩 Game 24、MATH-Geometry、Path Plan、BoxLift、Letters(sentence)、Blocksworld 这几个。
2. **绝对分数不可比**。归一化的 max 只在我这 5 个方法里取（论文是 10 个方法），加上模型不同，**只能比名次和方向**，不能比绝对值。
3. **论文的"inverse scaling / 过度自信用代码"只能部分对照**。本次用一个近似口径统计了代码使用率（见 3.5），方向与论文一致：不给指令时模型也会自发写代码（OnlyQ 在 Blocksworld 15%、Path Plan 14%），且"写了代码"不等于"代码有用"。论文 Table 3 的精确口径（按 turn 统计）没有严格复刻。

## 5. 三个思考模式的解读（本次自加的维度）

**B 组 ≠ A 组 + 一个滤镜。** 开思考后模型会把推导写进 `reasoning_content`，正文退化成很短的碎片（B 组正文中位数只有 16 个字符，42% 的调用正文 < 20 字符）。这些碎片常常**就是答案**（如 `<<<12/25/1937>>>`），所以短答案任务（BBH 系列）B 组不掉分；但需要正文带代码块/推导的任务（MATH-Geometry、Letters(sentence)、Path Plan）B 组会掉，因为 runner 的判分链路是"从正文抽代码块 → 执行 → 读 stdout → 裁判抠答案"，信息一少就抽错。

**B vs C 的差距（丢思考 vs 留思考）**：OnlyQ 94.8 vs 94.3、AllText 89.7 vs 91.4、AllCode+CoT 89.1 vs 90.5、AutoGen 92.7 vs 93.2、Sum 99.4 vs 99.7 —— **平均只差 0.7 个点**。也就是说，对这套"再多轮 refine + 汇总"的流水线，**思考内容下游用不用得上，影响很小**；真正起作用的是"开不开思考"（A→B 五个方法平均 +4.6 点）。

顺带一个好玩的读数：OnlyQ 上 B（94.8）比 C（94.3）还高。因为"只给问题"这种单轮设定里，把思考文本拼回正文反而给裁判塞了更多噪声（裁判要从长文本里抠答案）。

**A→B 的增益**主要来自：AllCode+CoT +11.9、AutoGen +5.6、OnlyQ +4.5。A 组里 code 类方法最差，恰恰是因为关思考时模型写的代码"能跑但思路错"（Blocksworld 只打印 `Move B from 1 to 2` 没包 `<<<>>>`，导致 JSON 抽取全空）。

## 6. 已知偏差（不修正就不能下结论的部分）

### 6.1 B 组 path_plan / BoxNet 的 0% —— 预算截断，非方法效应

`repro/truncation_audit.py` 扫描结果：

| 模式 | 样本 | 正文为空 |
|---|---|---|
| off | 1350 | 0 (0.0%) |
| strip | 1350 | **377 (27.9%)** |
| on | 1350 | 0 (0.0%) |

空正文 100% 集中在 strip 组的 `boxnet1`（5 方法 × 25 = 125）与 `path_plan`（5 方法 × 25 = 125），且这些调用的 `completion_tokens` **恰好等于 2500 预算**。定点探测（`repro/probe_truncation.py`，同一 prompt 分别给 2500 / 8000 / 16000）：

- 2500 → `out_chars = 0`（全被思考吃光）
- 8000 → `out_chars = 7`
- 16000 → `out_chars = 19~240`（答案出来了）

**结论：B 组这两个任务的 0% 是"预算不够"的产物，不能读成"丢弃思考有害"。** 敏感性重跑（8000 预算）结果见 6.2。

### 6.2 敏感性重跑（strip × path_plan/BoxNet1 × 8000 预算）

同一批样本，只把思考预算从 2500 提到 8000，重跑（结果在 `results/sens_strip_b8k/`）：

| 任务 | 方法 | 预算 2500 | n | 预算 8000 | n |
|---|---|---|---|---|---|
| Path Plan | OnlyQ | 0.0 | 25 | **32.0** | 25 |
| Path Plan | AllText | 0.0 | 25 | **20.0** | 25 |
| Path Plan | AllCode+CoT | 0.0 | 25 | **20.0** | 25 |
| Path Plan | AutoGen | 0.0 | 25 | **32.0** | 25 |
| Path Plan | Code+Text+Sum | 0.0 | 25 | **40.0** | 25 |
| BoxNet | OnlyQ | 0.0 | 25 | **16.0** | 25 |
| BoxNet | AllText | 0.0 | 25 | **12.0** | 25 |
| BoxNet | AllCode+CoT | 0.0 | 25 | **20.0** | 25 |
| BoxNet | AutoGen | 0.0 | 25 | **16.0** | 25 |
| BoxNet | Code+Text+Sum | 0.0 | 25 | 50.0 | 10（未跑完） |

**结论：B 组这两个任务的 0% 完全是预算产物。** 只要把预算从 2500 提到 8000，同样的样本、同样的模型，分数就从 0 变成 12~40%。而且恢复之后**方法的排序也恢复了**：Path Plan 上 Sum 40 > OnlyQ/AutoGen 32 > AllText/AllCode 20，与 A 组、C 组"Sum 最好"的方向一致 —— 这说明 B 组那两个 0% 不是"丢弃思考"的效应，只是预算把小任务的分数一起打没了。

⚠ 两点保留：

1. **但 8000 也不够**：B 组在 8000 下的 Path Plan（20~40%）仍明显低于 A 组（36~64%）和 C 组（52~72%）。也就是说预算解释了"0%"，但**解释不了"低"**——开思考 + 丢弃思考内容，在长规划任务上确实比关思考差。这是 B 组唯一真实存在的劣势，其余任务上 B 与 C 基本持平。
2. `BoxNet × Code+Text+Sum` 的 8000 数据只跑了 10/25 就按时间停掉（每样本 70~90 秒）。其余 9 个格子都是 25/25 满样本。

作为对照，C 组（留思考）在 8000 下的零散数据也显示同方向：Path Plan OnlyQ 60 → 96、AllText 68 → 100（n=25/7），说明**只要 thinking token 够，这个模型在这两个任务上的真实水平远高于 2500 预算下的读数**。所以 3.2/3.3 表里这三个任务（Path Plan、BoxNet、BoxLift）只能横向比方法，不能当"模型在该任务上的绝对能力"。

### 6.3 Blocksworld 上 AllCode+CoT 12%（A 组）—— 格式对不上，非代码执行失败

`benchmark/run_Blocksworld_baseline_methods.py:201-232` 会把 `response` 换成代码的 `result.stdout` 再去抽答案。模型写的代码是 `print("Move B from 1 to 2")`，**没包 `<<<>>>`**，于是 `extracted_answer_1.txt` 恒为 `<<<No answer found>>>`，而 `extracted_answer_2`（正文里的代码块）也不是答案 → 两个都对不上。手动跑同一份 `code_1_0.py`：`rc=0, stdout='Move B from 1 to 2'`，执行本身没问题。GPT-4o 当年会包 `<<<>>>`，这一代模型不会。

### 6.4 三个规划任务的低分是真实能力不足

BoxNet（0~16%）、Path Plan（A 组 36~64%，C 组 52~72%）、BoxLift（0~25%）三组都很低，与判分无关：这些任务要求多步空间规划，`deepseek-flash` 做不了。它们只能说明"方法之间差异"（Path Plan 上 Sum 64/72 明显更好），不能说明"整体难度"。

## 7. 复现过程中踩到并修掉的坑（供他人参考）

1. **`python3` 在 Windows 上不存在** → `env_win.py` 把所有 `["python3", ...]` 命令改写成当前解释器。
2. **`python -c "exec(open('C:\...').read())"` 的 `\U` 被当 unicode 转义** → 子进程 `SyntaxError`，stdout 永远为空，**整批实验的代码执行全程空转**（曾导致"代码方法看起来更差"的假结论）。修法：把该参数里的 `\` 全换成 `/`。
3. **模型白名单**：runner 里 `if model_name in [...]:` 走 API、否则走本地 HF 权重加载。国产模型名必须进白名单，否则报 `NameError: run_response`。
4. **判分器硬编码 `gpt-4o`**：`GPT_response(..., model_name='gpt-4o')` 的调用点要单独路由到裁判模型，且裁判始终关思考。
5. **样本计数写死 `total_sample_num += 1`**：所有 runner 都有这一行，是统一注入样本上限的好锚点；但 `big_bench_hard` 一个 runner 跑 4 个子任务，计数必须按子任务拆，否则第一个子任务把配额吃光。
6. **思考预算**：给 8000 时单次调用 70s、正文为空；2500 是这批任务的合理值（仍然是 B 组截断的根源，见 6.1）。
7. **`<<<...>>>` 抽取要用最后一个匹配**：开思考后正文里会掺中间猜测，取第一个会判错（曾把 C 组 letters 判成 12%）。
8. **字母计数任务的"位置"定义必须写进题面**：删空格后编号、标点也占位，否则真值和模型的合理理解差 4 个位置。

## 10. 成本与 token 消耗

### 10.1 单价口径

DeepSeek 官方价目表（`deepseek-flash`，2026-11 版，单位：元/百万 tokens）：

| 项目 | 空闲时段 | 高峰时段 |
|---|---|---|
| 输入（缓存命中） | 0.02 | 0.04 |
| 输入（缓存未命中） | 1 | 2 |
| 输出 | 4 | 8 |

高峰时段 = 北京时间周一至周五 9:00–12:00、14:00–18:00（法定节假日除外），其余时间及周末按空闲价（半价）。本项目的跑批大多在夜间，但**今早 9:00 之后仍在跑**，所以高峰价占了一部分。

下面的费用区间统一按 **缓存未命中** 的输入价算（区间下界=全空闲、上界=全高峰），这是**偏保守的上界估计**；真实账单通常会低一些，因为多轮对话里历史部分会命中缓存。

### 10.2 总账（含所有跑批，包括返工）

| 阶段 | 调用次数 | 输入 tokens | 输出 tokens | 费用（元） |
|---|---|---|---|---|
| A 组（关思考） | 11,430 | 7.68M | 2.81M | 18.9 ~ 37.8 |
| B 组（丢思考） | 6,191 | 2.16M | 2.17M | 10.8 ~ 21.7 |
| C 组（留思考） | 6,027 | 5.15M | 2.20M | 13.9 ~ 27.9 |
| 敏感性补跑（8000 预算） | 1,217 | 1.21M | 3.35M | 14.6 ~ 29.2 |
| 冒烟测试 | 1,465 | 0.89M | 0.32M | 2.2 ~ 4.3 |
| 调试探测 | 46 | 0.01M | 0.03M | 0.1 ~ 0.3 |
| **废跑①**（`-c` 路径 bug 未修时，结果已作废） | 10,537 | 4.49M | 1.68M | 11.2 ~ 22.4 |
| **废跑②**（思考预算 8000 未调时，结果已作废） | 19,159 | 12.76M | 8.05M | 45.0 ~ 89.9 |
| 其它 | 12 | 0.00M | 0.00M | 0.0 |
| **合计** | **56,084** | **34.34M** | **20.61M** | **116.8 ~ 233.6** |

若输入大量命中缓存（0.02~0.04 元/百万），输入侧费用只有 0.7~1.4 元，总费用约 **83 ~ 166 元**。

**有效实验 vs 返工**：真正产出结论的是前 4 行 —— 24,865 次调用、16.2M 输入、10.5M 输出，约 **58~116 元**；剩下约 **56~112 元** 花在两次返工（①修 bug 前的 10,537 次调用 ②思考预算过大导致 73 秒/次的那批 19,159 次调用）和冒烟测试上。

### 10.3 钱花在哪了

1. **输出 token 是主要成本项**。24 组数据里输出 20.6M tokens，按空闲价 4 元/百万就是 82 元，占总成本一半以上。输出贵的根因是"开思考" —— 每个样本要额外生成几百到几千个 reasoning token。
2. **单个样本要 1~5 次串行调用**。这套方法是"生成 → 执行代码 → 裁判判分 → 决策是否再修一轮"，一个样本平均 8.5~9 次调用（A 组 11,430 次 / 1,350 样本）。
3. **开思考的两组比关思考贵得多**。同样 25 样本/任务，A 组输入 7.68M（因为它先跑了 50 样本）、C 组 5.15M 而 B 组只有 2.16M —— B 组省的是"思考文本不往下游传"，输入的 history 因此短了很多。这也是 C 组比 B 组贵 30% 的原因。
4. **两次返工占了总花费的一半**。废跑②尤其贵（45~90 元）：当时把思考预算设成 8000，单次调用 70 秒、正文还经常为空，跑了一夜只完成 32/60 组合，最后全部作废。

### 10.4 每个样本的平均成本

按有效实验统计（4,050 个样本 × 3 组）：约 **0.014 ~ 0.029 元/样本**。也就是说，如果预算再压缩：

| 做法 | 预计费用（1 组 15 任务 × 5 方法） | 说明 |
|---|---|---|
| 25 样本/任务（本次口径） | 12 ~ 25 元 | 结论已够稳 |
| 10 样本/任务 | 5 ~ 10 元 | 大任务波动会变大（±10 个百分点） |
| 只跑 A + C 两组 | 省 1/3 | 放弃"丢思考 vs 留思考"这个维度 |
| 只跑 `OnlyQ / AllText / Code+Text+Sum` 3 个方法 | 省 40% | 论文的主要结论（组合方法最优 + 代码不一定好）仍能验证 |
| 换 Qwen / Kimi 做迁移验证 | 按各家单价另算 | 用 `python -X utf8 run_all.py --estimate` 先估调用次数再报价 |

## 11. 自己重跑一遍的最短路径（零基础照着敲）

前置：`C:\Users\13988\Desktop\prog\CodeSteer\.env` 里有一行 `DEEPSEEK_API_KEY=sk-...`；Python 用 `C:\Users\13988\anaconda3\envs\CodeSteer\python.exe`（依赖已在 `repro/vendor/`，不需要 pip）。

```powershell
cd C:\Users\13988\Desktop\prog\CodeSteer\repro

# ① 先体检：能不能连上 API、python3 补丁是否生效（不花钱或只花几厘）
& 'C:\Users\13988\anaconda3\envs\CodeSteer\python.exe' -X utf8 env_win.py

# ② 先估花费，别直接开跑（这一步不发请求，只算样本数 × 调用次数）
& 'C:\Users\13988\anaconda3\envs\CodeSteer\python.exe' -X utf8 run_all.py --estimate --cap 25

# ③ 小样试跑：每任务 2 个样本，确认整条链路通了
$env:THINK_MODE='off'
& 'C:\Users\13988\anaconda3\envs\CodeSteer\python.exe' -X utf8 run_all.py --cap 2 --tasks game24,gsm,MATH_geometry

# ④ 正式跑（一个思考模式一组，跑完再换）
$env:THINK_MODE='off'          # 或 'strip' / 'on'
& 'C:\Users\13988\anaconda3\envs\CodeSteer\python.exe' -X utf8 run_all.py --cap 25 2>&1 | Tee-Object -FilePath logs\run_off.log

# ⑤ 出表
& 'C:\Users\13988\anaconda3\envs\CodeSteer\python.exe' -X utf8 summarize.py --per-task-cap 25 --md results\summary_final.md
```

几个必须知道的点：

- **`$env:THINK_MODE` 是三组实验的开关**（`off` / `strip` / `on`），`$env:REPRO_THINK_TOKENS` 默认 2500 —— 别调成 8000（会 70 秒一次并把正文挤空，见 6.1）。
- **断点续跑**：中途挂了直接重跑同一命令，已完成组合会按 `logs/main_run_{mode}.json` 跳过；要重跑某任务加 `--force`。
- **不要并行跑同一个「模式 + 任务」组合**，会互相覆盖 `save_input/`。要并行就按任务分片（`--tasks`）并用不同的 `$env:REPRO_STATE_TAG`。
- **预算**：按第 10.4 节，25 样本 × 15 任务 × 5 方法一组约 12~25 元，三组约 40~75 元。
